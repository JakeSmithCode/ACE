Orientation and guardrails for working in this repo. Read this before changing engine or contract code.

## What ACE is

An asynchronous, server-authoritative Valorant esports management sim. You own a club; you set rosters/comps/tactics ahead of time; a deterministic engine resolves every scheduled match on a tick; you watch matches back on a 2D viewer. A match is a pure function of `(rosters, tactics, patch, seed)`, so "live" and "replay" are the same stored data, and any round can be rewound and re-simulated. Full design: `docs/DESIGN.md`.

The bet: we don't compete on 3D fidelity, we compete on **interrogability** — a tactical instrument you can rewind, fork, and x-ray.

## The one rule that everything depends on: determinism

The engine is pure. Same input → byte-identical output, forever.

- **No `Math.random()`. Ever.** Use the seeded PRNG in `packages/engine/src/rng.ts` (mulberry32). Thread the `Rng` instance through; never create a second source of randomness.
- **No `Date.now()`, no `performance.now()`, no wall-clock, no I/O** inside `simulateMatch` or anything it calls.
- **No iteration-order nondeterminism.** Don't rely on `Object.keys` order across engines, `Set`/`Map` insertion quirks, or floating-point that varies by platform in a way that branches the sim. Sort explicitly where order matters.
- If you add a system that needs "randomness," it draws from `rng`. If it needs "time," it uses the round's normalized `t` (0..1).

**How to verify after any engine change:** run `pnpm sim -- --seed 42` twice and diff the output — it must be byte-identical. Then run a spread of seeds and confirm every match completes (a side reaches 13) and the ending-method mix looks sane. Determinism breaking is the highest-severity bug in this codebase; it silently kills replays, debugging, and server resolution.

## The spine: the timeline contract

`packages/shared/src/timeline.ts` defines `MatchInput` → `MatchTimeline`. The engine emits it; the viewer reads it. Neither side may know anything about the other beyond this shape.

- Treat the contract as an API. Changing it is a real decision, not a convenience — it ripples to the engine (producer) and the viewer (consumer) at once.
- Adding a field is usually safe (consumers ignore unknowns). Changing/removing a field, or changing the meaning of `t`, is breaking — update both sides and bump thinking about `version`.
- Event `t` is normalized 0..1 within its round. Keep it that way.

## The map pipeline (and why it's elegant)

A map's official minimap (`displayIcon`) is also its collision data: the alpha channel is the walkability mask — opaque = floor, transparent = wall. `packages/maps`:

- `scripts/build-navmesh.ts` reads alpha → a coarse walkable grid → `data/<map>.navmesh.json` (and a copy in `apps/web/public/` for the viewer).
- `src/navmesh.ts` runs A* on that grid (`pathfind`), plus the LOS/vision primitives (`losClear`, `inView`).
- To add a map: drop its `displayIcon` in `assets/` (and `apps/web/public/` so the viewer can show it), add anchors in `src/anchors.ts`, rerun `pnpm navmesh:all`. No hand-tracing. Everything downstream (routing, vision, future heatmaps) operates in the same 1000×1000 image space, so it all lines up for free.

**All 11 official maps are in** (navmesh + anchors): ascent, abyss, bind, breeze, fracture, haven, icebox, lotus, pearl, split, sunset. `pnpm sim -- --map <id>` resolves any of them; the viewer loads assets by `timeline.map`. Measure any map's balance with **`pnpm balance`** — an x-ray that sims a roster-symmetric mirror matchup (neutral tactics) across a seed spread and reports each map's attacker round-share, plant rate, and ending mix, flagging `ATK-SIDED`/`DEF-SIDED`/`STALLY`. Tune against the numbers, not by eye.

**Map-scale normalization is in.** `SPEED` is calibrated to Ascent, so a map whose pushes/rotations are longer in absolute image-units plays too fast for Ascent-speed defense. `mapScale(A)` derives a per-map factor from each map's characteristic distance (`charDist` = 0.6·mean(spawn→site) + 0.4·mean(mid→site)) over Ascent's, and multiplies every movement speed (`atkSpeed`, `rotSpeed`, authored-route + kill-point arrive) by it, so a push and a rotation cost the same *fraction of the round* on every map as on Ascent. Pure geometry, no per-map magic numbers — and **Ascent's scale is exactly 1.0, so seed 42 is byte-identical** (every arrive time ×1). It's threaded into `resolveRound` as a param so canonical + forks agree. This pulled the genuinely *mis-scaled* maps into balance (haven 63→57% attacker, split/lotus into band).

But **scale is not the whole story** — only Ascent is truly tuned. The residual offenders are *mis-shaped*, not mis-scaled: fracture/abyss/bind/pearl sit ~82–91% attacker with ~95% plant rate because their **sites are too far from `mid`** for the default procedural defense (which posts most bodies at mid) to contest — a placement problem `mapScale` correctly leaves alone (fracture's scale is ~1.14, near Ascent's). icebox/split lean defender-sided and sunset stalls ~37% of rounds. Fixing these is per-map anchor work (reposition `mid`/sites, measured with `pnpm balance`) — fiddly because moving `mid` also shifts `mapScale`, so eyeball tuning regresses as often as it helps. **Map rotation is live over a curated pool of the *balanced* maps**: the canonical `MAP_POOL = [ascent, breeze, haven, lotus, split]` (haven and lotus RETURNED with the site-anchor pass: their outer site anchors moved to the plaza MOUTHS — haven A+80s/C-60n, lotus A-60w/C+70e, snapped walkable — which shortens the unrecoverable ~700u A↔C rotations that made a wrong three-site read fatal-proof for the attack; both measure `ok` at 54.2 / 54.3 with sane plants and stalls. The fix was found by a MEASURED sweep (the mirror harness over candidate anchor points), not eyeballing — re-sweep before moving any anchor again. Two fixes already tried and MEASURED NULL — don't re-run them: a 3-site read-stack floor of 2 made both WORSE (60.9→68.4 / 62→65: a 3-site read is right only ~1/3 of the time, so extra commit mostly pays the wrong-read rotation tax — the mid pool IS the three-site flexibility), and a haven `mid`-anchor sweep (7 walkable candidates toward the sites, mirror-measured) made every candidate worse still (72-86% ATK — moving `mid` west pulls the flex bodies off the attackers' eastern approach lanes entirely). The real fix is likely site-anchor/defense-shape work, not `mid` or the split). **The DEFENSE-SHAPE pass (`defHedge`) then delivered that fix class and rescued two more**: `MapAnchors.defHedge` (authored per map like `defSpots`, absent = byte-identical) re-posts N mid-pool bodies as EXTRA site watchers — alternating off-site → read stack, so hedge 2 on a two-site map is the classic 2-2-1 — trading map-control flex for wrong-read insurance (same slot/jitter draw count, so the rng stream never shifts). Swept 0-3 over every out-of-pool map (80-seed mirrors, winners confirmed at 200): **bind hedge=3 lands 76.6→57.3 `ok`** (plant 95→72 — one watcher vs a five-man hit was the free-plant engine) and **icebox hedge=2 lands 41.0→51.6 `ok`** (its DEF lean was the mid pool OVER-intercepting a tiny map — the site probes never touched the real cause). The pool is now **8 maps** — `[ascent, bind, breeze, haven, icebox, lotus, pearl, split]`, all `ok` on `pnpm balance:check`. The rest are hedge-measured NULLS recorded in `anchors.ts` — fracture plateaus at 62 / abyss 64.5 with ZERO mid bodies left, sunset's 37% stall is LOS starvation not shape (hedge3 + cover-adjacent B-ring defSpots got 56.3 ATK / 25% time, the closest yet), and hedge×anchor-pull combos re-buy the stall coin — don't re-run them. `fixtureMap(seed)` assigns each fixture a map deterministically from the pool (the others stay out of rotation until tuned, like a real comp pool). The store loads a navmesh per pool map; `buildInput` sims on the fixture's map and **drops your authored plays on non-Ascent maps** (they're Ascent-coordinates — your dials still apply); the viewer loads the fixture's own png+navmesh to watch. **The editor is MULTI-MAP — one playbook per pool map** (`myPlays: Record<MapId, MapPlays>` in the store, `{attack, attack2, defense}` per map): a map picker drives the anchors/navmesh/minimap AND which playbook slot you author into; `buildInput` overlays the FIXTURE map's plays (dials stay map-agnostic), so your authored setups field on every map you've authored — previously plays existed only in Ascent coordinates and were dropped on 7 of 8 fixtures. Starters are DERIVED from the selected map's anchors (push-axis fan for attack, mid-bait + site shape for defense, every point snapped walkable — verified 0 off-mesh on bind), the editor preview sims the selected map, chips carry a ● when a map has authored plays, and old saves migrate their Ascent-era `myTactics` plays into `myPlays.ascent` once (`migratePlays`). Don't assume a non-Ascent map is balanced — the pool is the ones that are.

**N-site support is in** — the engine models N sites generally, not just A/B. `MapAnchors.sites` is `{ A; B; C? }` (the third is opt-in per map; `siteIds(a)`/`sitePt(a,s)` are the helpers), and **Haven and Lotus now field all three** (A/B/C, ~even split across them). The site dials generalize: attacker `siteBias` is a weighted pick over the fielded sites (`siteWeights`→`pickWeighted`, one rng draw), and defender `read` (`readIndex`) spans them (+1→A .. −1→last), so on a three-site map a wrong read can be **two rotations** away. The procedural defense stacks the read site, posts one watcher on **each** other site, and pushes the rest to mid. **Two-site is byte-identical**: `siteWeights`/`readIndex`/the defense split all reduce exactly to the old A/B math for `n===2` (the weighted pick over `[pA,1−pA]` is the same single `rng.chance(pA)` draw), so **seed 42 is unchanged**. Contract: `Round.site` and the `plant` event widened from `'A'|'B'` to `SiteId='A'|'B'|'C'` (additive — the viewer only displays it). The editor's `PlayEditor` renders a button per fielded site and mirror cycles through them; `Editor.vue` derives spawn+sites from `ANCHORS[MAP]` so it's correct for any map (the world is Ascent-only today, so it shows A/B). The natural next step is per-map anchor tuning so Haven/Lotus play *balanced*, not just complete.

When you touch geometry, reuse these primitives — don't write a second raycaster or a second notion of "walkable."

Team chemistry is in (the counterweight to the transfer market). Each player carries a `tenure` (seasons of shared play with their CURRENT club, on `Player`, additive/optional). Authored plays + kill points are in (the engine half of the cs-manager-style editor). `Tactics.defense.play?: Play` (in `@ace/shared/models`) lets an owner place defenders **exactly** instead of leaving them to the procedural read: `Play.plans` is one `PlayerPlan` per player — a `pos` to hold, plus an optional **kill point** `rotate: { pos, onDeathOf }` that re-routes that player when a named teammate dies. Routes are in (the path, not just the endpoint — works for both sides). `PlayerPlan.route?: Vec2[]` is the ordered waypoints walked **into** the hold: `[...route, pos]` is the full path the engine builds, so an empty/absent route means "start already on the hold" (the original byte-identical behaviour). Trading is in (round dynamics 1 of 3). `duel` now takes a numeric `surprise` edge (not `-1|0|1`); resolveRound composes it from vision (`±FIRST_SHOT`), pulses (`±FIRST_SHOT`), then a **trade**: a kill sets `winnerAg.exposedUntil = t + TRADE_WINDOW`, and a teammate who can see that exposed killer gets `±TRADE_EDGE` (via `Math.max/min`, so it flips a held first-shot but never weakens a bigger same-side edge). `exposedUntil` must reset to `-1` in the fork clones (it does) or odds drift. Trading favours the grouped side (~+13pt to attackers), and ~37% of kills get traded. Viewer tags trades in the kill feed (⇄) — derived from the event stream, no contract change.

**Fights are neither instant nor free** (the "actual players" combat layer). Three effects, all inside `resolveRound` so forks inherit them and True Odds machinery is untouched: (1) **HP + attrition** — every `Ag` carries `hp` (100/round); a duel WINNER takes return damage scaled by how contested it was (`rng.range(CHIP_LO, CHIP_HI) · (1−q) · 1.8` where `q` is the winner's own win probability — a dominant duel is near-free, a coin flip hurts; one extra rng draw per kill), floored at 5, and a wounded fighter duels worse (`WOUND_PEN`=0.08 edge per missing HP) — so the "entry wins at 40hp, gets cleaned up" chain emerges, and a 3K means surviving three fights of accumulating damage. On the canonical sample the average winner exits at ~56hp and ~46% of winners are under 60. (2) **Fight pause** — the winner halts at the kill spot for `FIGHT_PAUSE` (**balance-sensitive**: 0.018 tipped split DEF-SIDED 41.8; at 0.012 the pool is `ok` at 42.5–55.8 — pauses tax the pushing side hardest); pauses live on `Ag.pauses` and freeze the journey in `posAt` (progress = travel time NET of halts), so a contested push genuinely arrives late and a fresh killer is a stationary, known-position target through the trade window. `fireRotation` clears pauses (new path); fork clones must get a FRESH `pauses: []` (a shared ref would leak fork halts into the canonical pass). (3) **Fight facing** — the winner looks down the kill line for `FIGHT_FACE` (0.03) via `Ag.fightFace`, honoured by `facingAt` — tunnel vision that makes a fresh killer realistically flankable from its travel direction. **Contract (additive, version 1)**: `move` gained `pauses?: {t,dur}[]` and `kill` gained `hp?` (the winner's remaining health); the viewer mirrors `pausedTime` in `posWithDepart`/`facingOf` (every reconstruction call site passes `pauses`) and rebuilds the fight-face windows from the kill events, so kill pops/x-ray/heat stay exact. Fixing this exposed a **latent engine bug**: `loser.deathPos = posAt(loser, t)` ran AFTER `deathT` was set, so `posAt` short-circuited to the still-null `deathPos` — deathPos had been silently null forever (never read until fight-facing needed it); the death spot is now captured before marking dead. Tuning knobs: `FIGHT_PAUSE` (measure with `pnpm balance` before raising), `WOUND_PEN`, `CHIP_LO/HI`, `FIGHT_FACE`. **Non-lethal EXCHANGES** complete the layer: a near-coin-flip duel can break off without a kill (`GRAZE_MAX · closeness^0.4 · urgency`, one extra rng draw per off-site engagement) — both sides take light damage (`GRAZE_LO..HI`), watch each other (`GRAZE_FACE`), and that MATCHUP disengages for `GRAZE_COOL`, so firefights *build* (poke → poke → kill, wounds escalating via `WOUND_PEN`). Three guards hold balance, each learned by measurement: the cooldown is **per-pair, not per-agent** (`Ag.grazed` record — a per-agent cooldown let one attacker poke an anchor BLIND for the whole team, farming lotus to 58-59% ATK); **fights at the site always commit** (`nearSite`, `SITE_R·1.5` — site grazes delayed plants into 14-17% lotus stalls; note the `!nearSite &&` short-circuit means near-site fights draw NO graze roll); and **urgency fades pokes as the clock runs** (`1 − t·1.6`). Wounds are deliberately light — deep grazes (10-42) let the grouped side clean up wounded defenders. The exchange rate **follows map geometry** (breeze/split ~1.3-1.4/round of running mid gunfights; execute-heavy ascent/haven ~0.1-0.3 — the thesis working). **Weapons now have a real identity, not just a quality tier**: `W_DMG` scales damage by the gun (graze damage carries the SHOOTER's weapon; the winner's return-chip carries the LOSER's — beating an eco Classic is near-free, trading up into a rifle costs real HP), and `W_RANGE`+`rangeEdge(weapon, d, set)` gives each weapon a range personality inside the ENGAGE envelope (bands `RANGE_CLOSE`=70 / `RANGE_LONG`=125): a **SET** Operator dominates a held max-distance angle (+6) and crumbles when rushed (−7), SMGs/pistols invert — and the positive half applies **only to a stationary shooter** (`isSet` — you can't scope on the run), so the identity rewards holds. Both are post-draw scales / pure functions (no new rng draws — the stream shifts only where a duel probability flips). This dropped the average winner-exit HP to ~48 (rifle return fire bites). **The GUNPLAY layer completes the weapon model**: (1) **headshots** — each kill rolls `hs` from the winner's AIM + dominance (`HS_BASE`/`HS_AIM`/`HS_DOM`, drawn BEFORE the chip in fixed order): ~33% of kills on the canonical sample (the pro band), and a headshot's return-chip is ×`HS_CHIP` (0.3) — HS winners exit at ~75hp vs ~53 for body kills, so sharp-aim players visibly win CLEANER, not just more often (aim also shrinks non-HS chip ×(1.3−aim·0.005) and hardens graze pokes ×(0.8+aim·0.004) — all post-draw); the kill event carries additive `hs?`, the feed shows the ⊙, the x-ray explains it. (2) **rate of fire as RECOVERY** — the winner's `FIGHT_PAUSE` scales by `W_HANDLING` (Op 1.6× re-chamber, SMG 0.8×), and since pauses are contract DATA the viewer needs no mirror. (3) **reloading** — `inPause()` marks the post-kill recovery window: a mid-recovery fighter duels at `RELOAD_PEN` (6) and forfeits the set-weapon bonus (`isSet && !reloading` — you're not scoped while re-chambering), so getting traded mid-reload is mechanically true. Literal ammo/bullet counting is deliberately NOT modeled — at `STEP` 1.5s-granularity a duel is a burst commitment, and the recovery window carries the fiction honestly. (4) **armor rides the buy** — `ARMOR_MUL` (full 0.72 … eco 1.0) scales INCOMING chip+graze damage only (never the duel win — `TIER` carries buy quality there), so a bought-up team sustains multi-fight rounds (full-buy winners exit ~69hp) while an eco is fragile flesh; the economy now expresses through attrition end-to-end. HS% is tallied per player in the season stat leaders (`/stats` `hsPct`) and the post-match box score — star aim identity legible across a season. Contract: additive `dmg` event (`{from,to,dmg,hp}`, one per direction); consumers that only know kills skip it. The viewer draws a graze as a thin dashed tracer + a hit-flash on the target ring and mirrors `GRAZE_FACE` in the fight-face windows. **Live HP is on the map**: each agent wears a depleting ring-arc reconstructed per-frame from the round's `dmg`/`kill` hp checkpoints (scrub-correct — the last checkpoint ≤ T), hidden at full health so an arc *is* a story: green once hurt, amber ≤60, a red pulse when wounded ≤35 (pairing with the engine's hesitation halts) — who's hurt, at a glance, no contract change. **WOUNDED HESITATION** closes the attrition loop with visible behaviour: a fighter under `WOUNDED_HP` (35) who is **mid-travel** (`midTravel` — departed, en route net of pauses) hitches for `WOUND_PAUSE` (0.018) after surviving a graze, and a wounded duel WINNER's recovery pause is extended by the same — so a shredded survivor visibly staggers instead of gliding on, and (since pauses freeze the journey) genuinely arrives later, a real cost that compounds `WOUND_PEN`. It reuses the existing `Ag.pauses` contract data (no new fields, no new rng draws — the viewer replays it for free; ~5.9 pauses/round on the canonical sample, 30 agents stacking multiple halts). The `midTravel` gate is load-bearing: an un-departed holder or an arrived anchor never pauses (nothing to freeze), only movement pays. **Clutch tracking** rounds out the stat identity: the server's `tallyTimeline` replays each round's kill order over per-side alive-sets, records the player left in a 1-v-2+ (`clutcher`), and credits a **clutch** when his side wins the round — surfaced in `/stats` (`clutch`) and the season leaders' gold `CL` column (1vX conversions, a different axis from raw frags). Knobs: `WOUNDED_HP` (the stagger threshold), `WOUND_PAUSE` (how hard a wounded body hitches — it's a pause, so measure with `pnpm balance` like `FIGHT_PAUSE`). **The MULTI-LEG move contract is in** (additive, version 1): an agent whose plan changes mid-round walks several journeys, carried as `MoveLeg[]` in the move event's `legs` — the base fields ARE leg 0 (an old consumer plays it and freezes at its end, graceful), each leg departs at its own absolute `departT` with its own `pauses`/`hold`, and the active leg at t is the last one departed. Engine side it's nearly free: during resolution t only moves forward past each re-path, so `posAt`/`facingAt` always operate on the CURRENT leg's fields — completed legs are archived on `Ag.doneLegs` (emission-only; fork clones get a FRESH `doneLegs: []` like pauses) by `beginLeg`, which `fireRotation` now rides. The viewer picks the active leg via `legAt`/`posLegs`/`faceLegs` wrapping the existing single-leg math (every reconstruction call site — render, x-ray, kill pops, spike, heatmap — goes through them; the trap hitch only ever rides leg 0). ## The world layer (`@ace/world`) — Phase 1 begins

`@ace/world` is the persistent-world core: it generates a league and resolves a season, and it is **pure and deterministic exactly like the engine** (same `Rng` from `@ace/engine`, the navmesh injected, no `Date`/`Math.random`/I/O). A whole season is a function of one seed. This is deliberate: the **single-player loop runs it client-side now, and the Phase-2 server worker will run the same code** to resolve scheduled ticks — no fork, no rewrite.

- `clubs.ts` — `makeLeague(seed, n)` → `Club[]` (`{ team, tactics, strength }`). Rosters are role-shaped (`ROLE_SHAPE` biases each role's attributes so identity is legible in the stat line), handles are drawn **without replacement** from a global pool (the engine assumes unique handles within a match — keep them globally unique so cross-club matches never collide), and strength descends across the field with noise (a hierarchy, not a fixed ladder). `makeTactics` varies the dials around sane ranges so AI orgs feel distinct.
- `schedule.ts` — `roundRobin(n)` / `doubleRoundRobin(n)` via the circle method (n even). A season is `Matchday[]`, each a set of `{home, away}` club-index fixtures.
- `divisions.ts` — the **rank pyramid** (DESIGN §17). The world is `DIVS` tiers of `DIV_SIZE` clubs — the pro leagues up top (`Premier`, `Challengers`) then the solo-queue ladder (`Radiant`…`Iron`), 11×16 = 176 total (a 16-club division → a 30-match-day double round-robin; the store owns `DIV_NAMES`/`DIV_SIZE`/`PROMO`/`START_TIER`). `membersOf(division, d)` lists a tier's club indices; `divisionSchedule(members)` builds that tier's double round-robin (the circle method over `0..m-1`, mapped to real club indices); `promoteRelegate(division, tables, k, playoff?)` swaps the bottom `k` of each higher tier for the top `k` below at season's end, returning the new `division` map + the `DivMove[]` for a banner. **A promotion PLAYOFF contests more spots** (`playoffs.ts#runPromotionPlayoff`, injected via the optional `playoff` callback so match resolution stays the caller's): after the auto `k`, the lower tier's next `PLAYOFF_SLOTS` (#3/#4) challenge the upper tier's at-risk band (#13/#14) in a cross-seeded 4-team bracket — **both Bo3-semifinal winners go up, both losers go down** (a showcase Bo5 final crowns the playoff trophy, cosmetic). Each boundary's playoff is net-zero for tier populations (conservation holds), and **omitting `playoff` is byte-identical** to the plain swap (the world/season CLIs are unchanged). The single-player store full-sims YOUR boundary (watchable, your tactics drive it) + quick-resolves the rest; `advanceWorld` quick-resolves all (flat worlds run it, the grouped funnel doesn't). Pure — `division` is store state (a club-index → tier map), so the engine, the `Club` type, and seed 42 are untouched. **Resolution is split by relevance: only YOUR tier full-sims** (5 fixtures/match-day, watchable); every other tier is `quickResult` (a deterministic strength-vs-strength scoreline, no engine call), so a 176-club world still sims a season in seconds. You start mid-table in Gold (`START_TIER`) and climb; promotion/relegation runs across all 11 boundaries in `advanceSeason`, income scales by tier (`divMult`), and the transfer board is scoped to clubs within a tier of you (`marketEligible`). **The horizontal fan-out is in** (docs/PHASE2.md §3, the at-scale shape): `(tier, group)` is a real division dimension, so a tier can be **many parallel divisions**, wider toward the base (a pyramid like real football / VALORANT ranked). `createWorld(seed, { layout })` takes the groups-per-tier layout (e.g. `[1,2,4]`) and assigns the strength-descending field to `(tier, group)` slots (`assignDivisions`, snake-seeded by strength); `worldDivisions(w)` lists every division, and `resolveSeasonDay`/`simulateSeason` schedule + resolve across all of them. The **funnel** (`funnelPromoteRelegate`) handles promotion/relegation between tiers of differing group counts: the bottom `k` of **each** group relegate, exactly that many promote up from the wider tier below (group winners first, ties by strength) so each tier's population is **conserved**, then every tier is **regrouped** (snake-seeded by strength) so groups stay full and balanced. ## The server tick core (`@ace/server`) — Phase 2 begins

`apps/server` is the persistence + scheduling layer the async-PvP world runs on (`docs/PHASE2.md`). It owns **no** simulation math — it loads a world, calls the pure `@ace/world` functions, and persists. The two pieces in:

- **The persistence boundary** (`store.ts`): an **async** `WorldStore` interface — a world snapshot, the season's `fixture` rows, and a `tick_log` (the idempotency key `unique(world, season, day, kind)`). It's async so a real DB store fits behind it (the `MemoryStore` just resolves immediately); the tick worker + HTTP layer await every call, so swapping stores changes **no resolution code**. **Durable persistence is in** (`pg.ts`): `PgStore` + `PgAccountStore` implement the same interfaces over a minimal injected `Queryable` (which `pg.Pool` satisfies — **zero-dep**, nothing imports `pg`); the `WorldState` is stored verbatim as `jsonb`, fixtures + `tick_log` as rows (the PK *is* the idempotency key). SQL: `infra/migrations/0002_worldstore.sql`. Verified without a live DB by **`pnpm run server:pg`** — PgStore over an in-memory `Queryable` fake (the exact statements `pg.ts` issues) ticks **3 seasons byte-identical to `MemoryStore`**, idempotency rejected by the PK, the auth flow matches. The async refactor left the resolution math untouched, so `pnpm run server` is byte-identical (5940 fixtures · 114 ticks). `loadWorld` copies out (a row read), so callers can't mutate stored state.
- **The tick worker** (`tick.ts`): `runTick(store, id, opts?)` resolves the world's **current match-day** (idempotent — guarded by `tick_log`, a retried/crashed job never double-resolves) or, when the season's match-days are exhausted, rolls the season over (`advanceWorld`: playoffs → settle → develop → patch → promote/relegate). ## The web app's async-PvP client (the Match Center)

## A settled contract decision (don't relitigate by accident)

Rendering vision needed facing in the timeline. The decision made: expose **only `move.hold`** — the unit heading an agent looks down once it reaches the end of its path. Facing *while moving* is the path's own direction, so a consumer reconstructs facing at any `t` from `path` + `arrive` + `hold` (see `facingOf()` in the viewer, which mirrors the engine's `facingAt()`). This was chosen over a per-tick facing track because the engine doesn't model look-arounds — sampling would just store a function the viewer can already derive. It's additive, so `version` stayed `1`. If you ever add genuine mid-path look mechanics, that's when a sampled track earns its keep — and its own `version` bump.

The viewer fetches `apps/web/public/<map>.navmesh.json` (emitted by `pnpm navmesh` alongside the engine's copy) and reuses the engine's exact LOS sampling to clip cones, so what you see matches what the engine resolved. Don't write a second raycaster.

## Tuning knobs (gameplay feel, not correctness)

These shape how lethal getting caught off-guard feels; expect to dial them after watching matches back. Keep them named constants, not magic numbers scattered in logic:

- `FOV` (cone half-angle, ~60°) — how much peripheral awareness an agent has.
- `FIRST_SHOT` — the edge for seeing an unaware enemy first; the single biggest lever on backstab/retake lethality.
- `SMOKE_R` / `SMOKE_R_UTIL`, `SMOKE_DUR` / `SMOKE_DUR_UTIL` — smoke size/duration and how hard they scale with utility; the bigger lever on how much space utility buys.
- `PULSE_R` / `PULSE_R_UTIL`, `PULSE_DUR` / `PULSE_DUR_UTIL` — recon/flash reach and window; the lever on how decisive entries are.
- `TRAP_R` / `TRAP_R_UTIL`, `TRAP_DUR` — sentinel flank-trap reach and how long it stays armed; the lever on how hard a lurk/flank is punished (and how much a sentinel is worth).
- `TRAP_SLOW` — round-fraction an enemy is delayed crossing a trap (the denial half of the trap); bigger = a tripped lurk/flank arrives further out of position. The first movement-affecting ability lever.
- `FORM_SWING` — match-night form band (± duel edge per player). Bigger = more star/dud variance night to night; keep it fair and legible, never a mugging.
- `HOLD_BONUS` + the defender rotation speed (`arriveTime(path, 0.6)`) — together the lever on how hard a wrong defensive read is punished; the heart of the tactics mind-game. Bigger hold / slower rotation = reads matter more.

To re-balance or measure a tuning change, an A/B is easy: gate utility generation, or set every non-utility attribute equal across two rosters and vary only `utility` to confirm the high-utility side wins (~58% of matches at 92 vs 18).

## Conventions

- Monorepo: pnpm + turbo. Packages are consumed as source via path mapping (`@ace/shared`, `@ace/maps`, `@ace/engine`) — tsx runs the engine, Vite bundles the app — so packages have no separate compile step; their "build" is a typecheck (`tsc --noEmit`). Don't add `rootDir`/`outDir` emit back to them, and don't commit `.js`/`.d.ts` next to `.ts` source (the web build is `vue-tsc --noEmit && vite build` specifically to avoid emitting those).
- Commit artifacts that make a cold clone work: the committed sample `apps/web/public/timeline.json` and `packages/maps/data/*.navmesh.json` are intentional so `pnpm install && pnpm dev` works without running the engine first. Regenerate them when their inputs change.
- Before opening a PR / finishing a task: `pnpm typecheck` green, `pnpm sim` deterministic across two runs and complete across several seeds, `pnpm build` green. **`pnpm sim:check`** is the automated determinism golden test (the manual two-run diff, as a gate): it re-sims the canonical seed-42 input and fails non-zero if the output isn't run-to-run byte-identical *and* an exact match for the committed `apps/web/public/timeline.json` — run it in CI and after any engine change (if the change was intentional, regenerate the sample with `pnpm sim -- --seed 42` and commit it on purpose).
- TypeScript strict is on (incl. `noUnusedLocals`) — no dead variables.
